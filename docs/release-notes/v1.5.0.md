Version 1.5.0 adds a lot to what Horizon Events can detect, how it tells you, how you search, and how it is run on a shared server. Everything new is off or empty until you use it, and nothing new sends data anywhere unless you set it up.

## What's new

- **More Windows detections.** Five new rules: sign-ins with explicit credentials (HZ-013), NTLM network sign-ins from the internet (HZ-014), someone added to the Administrators group (HZ-015), suspicious PowerShell scripts (HZ-016) and USB devices (HZ-017). PowerShell scripts are only visible if Windows script block logging is turned on.
- **Sign-in locations.** Two rules, new country (HZ-018) and impossible travel (HZ-019), and a location line on alerts. They need a location database file that you download yourself (for example MaxMind's free GeoLite2 City) and choose in Settings. Without it they do nothing.
- **Rules of your own.** The new *Detection rules* page lets you switch rules off, change the settings of built-in rules, write rules with a condition builder, and import Sigma rules. Every change can be tested on the last 1 to 90 days of your events first, without saving anything.
- **Notifications.** Send new alerts to a webhook, Slack, Discord or an email address (Settings > Notifications), each with its own lowest severity and a Send test button.
- **Owner, tags and late alerts.** Say who is working on an alert and label it; the Alerts page filters by both and marks alerts that waited longer than their target.
- **Scheduled reports.** A daily or weekly report saved to a folder and, if you like, emailed.
- **Search.** The event search understands things like `user:admin severity:>=high -ip:10.0.0.0/8`, with saved searches and CSV or JSON export.
- **Live updates.** Screens refresh the moment new events or alerts arrive, instead of waiting for the next timer.
- **More sources.** An optional network syslog receiver, the Linux systemd journal, the macOS system log, and the Windows PowerShell log.
- **Threat lists.** Import your own list of bad addresses, file hashes and domains (STIX, MISP or plain text) and see matches on alerts. Nothing is uploaded.
- **Sign-in with roles for servers.** Docker and server installs can require sign-in with viewer, analyst and admin roles (set `HORIZON_AUTH=1`). The desktop app is unchanged: it still needs no accounts.
- **Update check.** Settings > Updates tells you when a newer release exists, when you ask or once a day if you switch that on. It never installs anything.
- **A customizable overview.** Choose which panels the Overview shows, their order and the chart's time range.

## Fixed

- The README's command for building the installer had a stray character in the script name and did not work as written.
- The README no longer says that Windows support is for exported logs only, or that the dashboard only polls.

## Good to know

- The text of the new screens is in English only for now; older screens keep their 12 translations. The names and advice of the new detection rules are translated.
- The new location, syslog, journald, macOS and notification features were tested with simulated data and fake servers, not against real MaxMind files, mail servers, Slack, Linux or Mac machines. Please use *Send test* on each notification channel, and tell us what you find.
- The syslog receiver has no login. It listens on this computer only unless you change it, so expose it only to networks you trust.
- Passwords for sign-in need at least 12 characters. There is no single sign-on or two-factor sign-in yet.
- The Windows installer is still unsigned unless the signing secrets are set up for the release.

## Upgrading

Install over the existing version; your data is kept and the new tables are created on the first start. A server install needs `pip install -r requirements.txt` again (two small packages were added: pyyaml and maxminddb). Sign-in stays off unless you set `HORIZON_AUTH=1`.
